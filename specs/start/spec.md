# Техническое задание: Система «Управление задачами» — pcdev-0005

## 1. Введение

Система «Управление задачами» (Task Admin) предназначена для управления пользовательскими задачами: их создание, просмотр списка и удаление. Настоящий документ описывает функциональные требования, сформулированные на основании файла сценариев `taskadmin.feature` (формат Gherkin, язык: русский).

Цель системы — позволить пользователю отслеживать запланированную работу путём ведения собственного перечня задач.

## 2. Роли и общие положения

- **Пользователь системы** — единственная роль, работающая с задачами.
- Пользователь управляет только своими задачами (у каждой задачи есть владелец).
- Система должна обеспечивать действия «создание задачи», «просмотр списка задач» и «удаление задачи».

## 3. Сущность «Задача»

### 3.1. Структура данных

Задача хранится и передаётся как объект со следующей структурой:

```json
{
  "id": "1693488027123",
  "title": "Подготовить отчёт",
  "priority": "высокий",
  "startDate": "2023-08-31",
  "done": false,
  "owner": "Иванов",
  "createdAt": "2023-08-31T12:00:00.000Z"
}
```

| Поле | Тип | Обязательное | Описание |
|------|-----|--------------|----------|
| `id` | строка | да | Уникальный идентификатор задачи (присваивается системой при создании) |
| `title` | строка | да | Текст названия задачи (задаётся пользователем) |
| `priority` | строка (перечисление) | да | Приоритет задачи: «высокий», «средний», «низкий» |
| `startDate` | строка (дата) | нет | Дата начала задачи в формате `ГГГГ-ММ-ДД` (задаётся пользователем; может отсутствовать) |
| `done` | булево | да | Признак выполнения задачи (по умолчанию `false`) |
| `owner` | строка | да | Владелец задачи — имя текущего пользователя, создавшего задачу; определяет принадлежность задачи |
| `createdAt` | строка (ISO 8601) | да | Дата и время создания задачи в формате UTC |

### 3.2. Примечания

- В сценариях фичи используется приоритет «высокий»; значения приоритета допускают «высокий»/«средний»/«низкий».
- В клиентском приложении структура формируется функцией `createTask()` (`app.js`) и сохраняется в `localStorage`.
- Текущий пользователь выбирается в интерфейсе («Пользователь»); имя сохраняется в `localStorage` (ключ `taskadmin.currentUser`), а задачи каждого пользователя хранятся под отдельным ключом `taskadmin.tasks.<имя>`.

## 4. Функциональные требования

### 4.1. Создание новой задачи

- Система должна позволять пользователю создавать задачу с указанием **названия**, **приоритета** и необязательной **даты начала**.
- После ввода данных пользователь сохраняет задачу.
- При успешном сохранении система подтверждает создание задачи.
- Созданная задача должна отображаться в списке задач пользователя.
### 4.2. Просмотр списка задач

- Пользователь запрашивает список задач.
- Система возвращает **все задачи, созданные данным пользователем**.
- Каждая задача в списке отображается с указанием **названия**, **приоритета** и, при наличии, **даты начала**. Выполненные задачи визуально отличаются (зачёркнутое название).

### 4.3. Редактирование задачи

- Система должна позволять пользователю изменять **существующую** задачу.
- Пользователь может изменить **название**, **приоритет** и **дату начала** задачи.
- Редактирование выполняется через форму создания, переведённую в режим изменения («Изменить» → форма заполняется данными задачи → «Сохранить изменения»).
- При успешном изменении система подтверждает изменение задачи, и обновлённая задача отображается в списке.
- Во время редактирования доступна кнопка «Отмена», возвращающая форму в режим создания без изменений.

### 4.4. Пустой список задач

- Если у пользователя нет созданных задач, при запросе списка система возвращает **пустой список**.

### 4.5. Отметка задачи как выполненной

- Система должна позволять пользователю помечать задачу как **выполненную** (кнопка «Готово») и возвращать её в работу (кнопка «Вернуть»).
- Выполненные задачи визуально отличаются в списке.

### 4.6. Удаление задачи

- Система должна позволять пользователю удалять **существующую** задачу.
- При успешном удалении система подтверждает удаление задачи.
- После удаления задача **не должна отображаться** в списке задач пользователя.
- При попытке удаления **несуществующей** задачи система сообщает об отсутствии задачи, а список задач не изменяется.

### 4.7. Поиск задач по названию

- Система должна позволять пользователю фильтровать список задач по **подстроке названия** (без учёта регистра).
- При вводе текста в поле поиска список мгновенно обновляется и показывает только подходящие задачи.
- Если ни одна задача не соответствует условию, отображается сообщение «Ничего не найдено».
- При очистке поля поиска отображаются все задачи (с учётом фильтра по статусу и сортировки).

### 4.8. Фильтрация по статусу

- Система должна позволять фильтровать список по **статусу выполнения**:
  - «Все» — все задачи;
  - «В работе» — только невыполненные (`done === false`);
  - «Выполненные» — только выполненные (`done === true`).

### 4.9. Сортировка списка

- Система должна позволять сортировать список задач одним из способов:
  - «По дате создания» (по умолчанию) — по убыванию/возрастанию `createdAt`;
  - «По приоритету» — «высокий» → «средний» → «низкий»;
  - «По дате начала» — по возрастанию `startDate`, задачи без даты в конце.
- Сортировка применяется к отфильтрованному (поиск + статус) списку.

### 4.10. Счётчик статистики

- Система должна отображать сумму по текущему списку задач: **«Всего: N • Выполнено: M»**.
- При отсутствии задач отображается «Задач пока нет».

### 4.11. Экспорт и импорт задач (JSON)

- Система должна позволять пользователю **экспортировать** все свои задачи в файл формата JSON (`taskadmin-<пользователь>.json`).
- Система должна позволять пользователю **импортировать** задачи из JSON-файла, заменяя текущий перечень задач пользователя.
- Импорт должен **валидировать** данные: отклоняются не-JSON-содержимое и записи без непустого названия; недопустимый приоритет заменяется на «средний».
- При некорректном файле система сообщает: «Некорректный файл импорта», а текущий список не изменяется.

## 6. Граничные случаи и обработка ошибок

- **Отсутствие задач:** возврат пустого списка без ошибки (см. сценарий 5.4).
- **Некорректные данные при создании:** при пустом названии или недопустимом значении приоритета создание должно быть отклонено с соответствующим уведомлением пользователя (требование уточняется, в фиче явно не задано).
- **Удаление несуществующей задачи:** при попытке удалить задачу, которой нет у пользователя, система должна сообщить об отсутствии задачи и не изменять список (см. сценарий 5.8).
- **Редактирование несуществующей задачи:** при попытке изменить задачу, которой нет у пользователя, система сообщает об отсутствии задачи.
- **Приоритет:** при неизвестном значении приоритета система должна отклонить создание задачи.

Примечание: перечисленные требования к валидации являются допущениями, дополняющими поведение, описанное в сценариях фичи.

## 7. Техника реализации

Система реализуется как **простое клиентское веб-приложение** на языке **JavaScript (vanilla JS)** без серверной части и внешних библиотек (кроме CSS/JS-библиотеки Bootstrap).

- **Стек:** HTML, CSS, JavaScript (vanilla). Никаких фреймворков и сборщиков.
- **Оформление:** Bootstrap 5 (подключается через CDN) для вёрстки и стилизации интерфейса; кастомный файл `styles.css` содержит только дополнительные стили (зачёркивание выполненных задач).
- **Хранение данных:** задачи сохраняются в браузере через `localStorage`. Текущий пользователь выбирается в интерфейсе; перечень задач каждого пользователя хранится под отдельным ключом (`taskadmin.tasks.<имя>`), что обеспечивает изоляцию данных между пользователями без сервера.
- **Интерфейс:** одностраничное приложение:
  - форма выбора/смены текущего пользователя (поле «Имя пользователя», кнопка «Сменить пользователя», подпись текущего пользователя);
  - форма создания/редактирования задачи (поле «Название», выбор «Приоритет», поле «Дата начала», кнопки «Сохранить/Сохранить изменения» и «Отмена»);
  - вывод подтверждения о создании/изменении/удалении задачи;
  - панель управления списком: поиск по названию, фильтр по статусу («Все»/«В работе»/«Выполненные»), сортировка («По дате создания»/«По приоритету»/«По дате начала»), счётчик статистики;
  - блок резервного копирования: кнопки «Экспорт в JSON» и «Импорт из JSON»;
  - список задач, где каждая задача отображается с названием, приоритетом и при наличии датой начала, с возможностью изменить, отметить выполненной и удалить задачу;
- **Валидация:** пустое название или недопустимый приоритет отклоняется с уведомлением пользователя.
- **Запуск:** достаточно открыть `index.html` в браузере; развёртывание/сервер не требуется.

Структура файлов:
- `index.html` — разметка страницы;
- `styles.css` — оформление;
- `app.js` — логика приложения (vanilla JS).

Структура файлов e2e-тестов:
- `package.json` — зависимости и npm-скрипт `test`;
- `playwright.config.js` — конфигурация Playwright (`baseURL: http://localhost:8080`, `testDir: ./e2e`);
- `e2e/tasks.spec.js` — e2e-тесты сценариев задач.

## 8. Тестирование (E2E, Playwright)

Функциональность проверяется сквозными (e2e) тестами на базе **Playwright** (Chromium, headless). Тесты запускаются против работающего веб-сервера `darkhttpd` на `http://localhost:8080`.

### 8.1. Запуск

```sh
./serve.sh start   # запустить darkhttpd на http://0.0.0.0:8080/ (если не запущен)
npm test           # выполнить e2e-тесты
```

Каждый тест перед выполнением очищает `localStorage` (`page.addInitScript`), обеспечивая изолированное начальное состояние.
